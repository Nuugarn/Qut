# สเปก QUT / BILL — ยืนยันแล้ว

อัปเดต 1 พฤศจิกายน 2026: ผู้ใช้สั่งนำตัว local รวมนี้เข้า repo Nuugarn/Qut อนุญาต commit/push branch codex และเปิด PR ตามคำขอนี้ ยังไม่รวม main หรือ deploy ข้อความด้านล่างเรื่องยังไม่เผยแพร่เป็นประวัติของการพัฒนาในเครื่อง

วันที่: 29 ตุลาคม 2026; แก้ไขตามคำยืนยันล่าสุด 30 ตุลาคม 2026
สถานะ: ผู้ใช้ยืนยันสเปกและอนุญาตให้เริ่มทำในเครื่อง โดยไม่เผยแพร่
Implementation อยู่ใน repo Qut-Bill ที่สร้างใหม่ รายละเอียดการใช้งานใน README.md และผลตรวจใน TESTING.md ไม่มีการสร้าง remote, commit, push หรือ deploy

## 1. เป้าหมายและโครงสร้าง
- เตรียม repository รวมใหม่ โดยเก็บ Qut และ Bill เดิมไว้
- กดชื่อเอกสารด้านซ้ายบนพร้อมลูกศร ▾ เพื่อเปิดเมนูเลือกใบเสนอราคา/ใบวางบิล ไม่มีแถบ QUT / BILL แยกด้านบน
- ไม่แสดงข้อความอธิบายการจำร่างบนหน้าปกติ แต่ยังจำร่างตามเดิม
- ปรับตามความคิดเห็นล่าสุด 30 ต.ค.: BILL ใช้ header รูปแบบเดียวกับ QUT แต่พื้นสีเขียว ชื่อเป็นข้อความล้วน ไม่มีโลโก้ B. หรือคำว่า BILL แยก
- เอาส่วน BILLING WORKSPACE/สร้างใบวางบิล/การ์ดสรุปเหนือเอกสารออก และลบเลขหัวข้อ 01/02 โดยเก็บชื่อหัวข้อไว้
- หัวตารางงวดเป็นสีเขียว ตัวอักษรขาว พร้อมเส้นตารางแนวนอนและแนวตั้งชัดเจน
- หัวตารางทุกคอลัมน์ต้องอยู่บรรทัดเดียวเมื่อพิมพ์; ไม่แสดงคำรอง “BILLING NOTE” ใต้ชื่อใบวางบิล
- รักษาหน้าตาของแต่ละแอปเดิม ไม่เปลี่ยนให้ใช้ดีไซน์เดียวกันในรอบนี้
- QUT และ BILL ทำเอกสารแยกกัน ไม่ส่งข้อมูลหรือสร้างเอกสารจากกัน
- ใช้กับงานโครงการ รับเหมา และบริการที่มีการแบ่งงวดเป็นหลัก
- แก้ข้อมูลบนเอกสารโดยตรง รวมถึงข้อมูลหัวเอกสารและรายการ ไม่ย้ายการกรอกหลักไปฟอร์มด้านซ้าย
- ไม่เพิ่ม framework หรือ backend เพียงเพื่อให้สลับ section ได้ การจัดโมดูลเป็นรายละเอียด implementation

## 2. ใบเสนอราคา QUT
- ราคารวมแต่ละรายการคำนวณจากจำนวน × ราคาต่อหน่วย ไม่ให้แก้ยอดรวมแถวแยกจนขัดกับสูตร
- งานเหมาระบุเป็น 1 งาน × ราคาเหมา ใช้ช่องรายละเอียดอธิบายขอบเขตงาน
- เก็บรายการ หมายเหตุ ค่าใช้จ่ายเพิ่มเติม วันยืนราคา ลายเซ็น และความสามารถเดิมที่ไม่ขัดกับสเปกนี้
- ส่วนลดท้ายเอกสารเป็นตัวเลือก ปิดไว้โดยค่าเริ่มต้น เมื่อติ๊กเปิดจึงมีช่องให้กรอกบนเอกสาร
- รูปแบบส่วนลดที่เสนอในสเปก: จำนวนเงินบาทหรือเปอร์เซ็นต์; ยังไม่เพิ่มส่วนลดรายบรรทัด
- เมื่อปิดส่วนลดต้องหยุดคิดและไม่แสดงใน PDF ไม่ใช่แค่ซ่อนแถวแต่ยังหักเงิน
- VAT เลือกไม่คิด / บวกเพิ่ม / รวมในราคา เริ่มต้นไม่คิด VAT
- คงความสามารถประมาณการหัก ณ ที่จ่ายเดิม ไม่ขยายไปเป็นระบบเอกสารภาษีหรืออ้างว่าครอบคลุมกฎภาษีทุกกรณี
- การแสดงผลต้องแยกยอดก่อน VAT, VAT และยอดรวมให้ตรงกับโหมดที่เลือก

## 3. ใบวางบิล BILL
- ใบหนึ่งแสดงแผนทุกงวด และยอดรวมของงวดทั้งหมด ไม่เลือกเรียกเก็บเฉพาะงวดใดในรอบนี้
- ใช้ต้นฉบับ Bill ก่อนรวมจาก sibling Bill/ (working copy ที่เก็บไว้ ไม่ใช่ย้อน Git HEAD ซึ่งเก่ากว่า)
- การกรอกและข้อมูลบริษัทกลับตามต้นฉบับ; หน้าตา header/ส่วนหัว/ตารางปรับตามความคิดเห็นล่าสุดข้างต้น
- กรอกเปอร์เซ็นต์กับจำนวนเงินแยกกัน เปอร์เซ็นต์เป็นข้อมูลอ้างอิง ไม่เปลี่ยนเงินที่กรอก
- ไม่มีช่องยอดงาน ไม่มีโหมด %/จำนวนเงิน ไม่มีคำเตือนยอดจัดสรรขาด/เกิน และไม่มีปุ่มเอกสารใหม่ที่เคยเพิ่ม
- รวมจำนวนเงินเป็นสตางค์และตรวจตัวเลขก่อนพิมพ์ตามต้นฉบับ
- คงการจำร่างระหว่างสลับเอกสาร/รีเฟรชไว้ โดยอ่านร่างจากเวอร์ชันรวมเดิมได้ ไม่คำนวณยอดที่บันทึกใหม่
- ไม่แสดงข้อความเรื่องอายุร่าง ข้อมูลบริษัทกดใส่จากปุ่มข้อมูลเดิม

## 4. ข้อมูลและอายุของร่าง
- จำร่าง QUT และ BILL แยกกันระหว่างเปิดแท็บ สลับ section และรีเฟรชแล้วข้อมูลไม่หาย
- เป้าหมายคือร่างระหว่างใช้งาน ไม่ใช่การจำเอกสารข้ามครั้งหรือคลังเอกสาร
- ใช้ session-scoped storage เป็นแนวทาง implementation; การคืนแท็บโดย browser อาจคืน session ได้ จึงไม่อ้างว่าปิดแท็บเป็นการลบข้อมูลอย่างปลอดภัย
- ส่งออกเฉพาะ PDF ไม่เพิ่มไฟล์งาน เปิดไฟล์งาน สำรอง/นำเข้า ประวัติเอกสาร หรือ cloud sync
- เอกสารแก้ทับได้เสมอ ไม่ใช้ revision หรือสถานะส่งแล้วล็อก
- ไม่ล้างข้อมูลจากแอปเดิมโดยอัตโนมัติระหว่างเตรียม repo ใหม่

## 5. ข้อมูลบริษัท
- QUT ใช้ข้อมูลบริษัทเริ่มต้นที่กำหนดไว้ในเว็บ; BILL กดใส่จากปุ่มข้อมูลตามพฤติกรรมเดิม
- แก้ข้อมูลเฉพาะใบได้ โดยไม่เปลี่ยนค่าเริ่มต้นหรือเอกสารอีก section
- ไม่บันทึกข้อมูลบริษัทที่แก้เป็นค่าเริ่มต้นข้ามครั้งในเบราว์เซอร์
- ใช้ preset/asset ที่มีอยู่จริงเป็นฐาน; การอัปโหลดโลโก้และตัวจัดการหลายบริษัทไม่อยู่ในขอบเขตเพิ่มของรอบนี้

## 6. การพิมพ์และ PDF
- ทั้งคู่มีปุ่ม “พิมพ์ / บันทึก PDF” ใน header รูปแบบร่วมกัน และเปิดหน้าต่างพิมพ์ของ browser
- ปุ่มเรียกหน้าต่างพิมพ์ของ browser เช่นเดียวกับ Ctrl+P โดยผู้ใช้ไม่ต้องเปิดเมนู browser หรือกด shortcut เอง
- ผู้ใช้เลือกเครื่องพิมพ์หรือ Save as PDF ในหน้าต่างนั้น
- เปลี่ยน QUT จากการดาวน์โหลด PDF ผ่านภาพให้ใช้ browser print ตามที่ผู้ใช้เลือก
- พิมพ์เฉพาะเอกสารใน section ที่กำลังใช้งาน ไม่พิมพ์แถบสลับ section เมนู ปุ่มแก้ไข หรือเอกสารอีก section
- รองรับ A4 หลายหน้า ไม่บีบตัวหนังสือเพื่อให้เหลือหน้าเดียว
- หัวตารางซ้ำเมื่อข้ามหน้า ยอดรวมและลายเซ็นอยู่ท้ายเอกสาร
- ข้อความยาวต้องไม่ถูกตัดจากช่องกรอกเมื่อพิมพ์ ต้องตรวจด้วยไฟล์ PDF ที่สร้างจริง

## 7. สิ่งที่คงเดิมและสิ่งนอกขอบเขต
คงหน้าตาเฉพาะของแต่ละแอปและการสลับไทย/อังกฤษเดิม
ยังไม่เพิ่ม: เชื่อม QUT→BILL, ใบเสร็จ/ใบส่งของ, ติดตามชำระเงินจริง, ระบบลูกค้า/สินค้า, คลังเอกสาร, บัญชีผู้ใช้/ทีม, สองภาษาพร้อมกัน, เปลี่ยนธีมร่วม หรือระบบสร้าง template
การสร้าง remote repo, commit/push, ตั้ง GitHub Pages, ย้าย URL และเผยแพร่จริงเป็นการดำเนินงานภายหลังที่ยังไม่ได้สั่ง
ชื่อและตำแหน่ง repo ใหม่เลือกตอนเริ่ม implementation; ไม่ให้รายละเอียดนี้ขวางการยืนยันสเปกผลิตภัณฑ์

## 8. เกณฑ์ตรวจรับในการพัฒนาภายหลัง
1. พิมพ์ข้อมูลต่างกันใน QUT/BILL แล้วสลับและรีเฟรช ข้อมูลแต่ละ section ยังถูกต้องและไม่ปะปน
2. QUT: 1 งาน × 4,000 = 4,000 และการเปลี่ยนจำนวน/ราคาคำนวณยอดใหม่ตามสูตรเสมอ
3. ปิดส่วนลดแล้วไม่มีผลต่อยอดหรือ PDF; เปิดแล้วคำนวณตามชนิดส่วนลดที่เลือก
4. VAT บวกเพิ่ม: 10,000 → VAT 700 รวม 10,700; VAT รวมใน: 10,700 → ก่อน VAT 10,000, VAT 700
5. BILL: กรอก 30% กับ 10,000 บาทแยกกัน แก้เปอร์เซ็นต์แล้วเงินไม่เปลี่ยน รวมเฉพาะจำนวนเงิน
6. ร่าง BILL จากรุ่นรวมเดิมเปิดกลับมาได้ โดยคงค่าที่แสดงเดิมและไม่เปลี่ยนจำนวนเงินตามเปอร์เซ็นต์
7. ปุ่มพิมพ์เปิด browser print และ PDF มีเฉพาะ section ปัจจุบัน
8. ตรวจ PDF หน้าเดียวและหลายหน้า ภาษาไทย/อังกฤษ ข้อความยาว หัวตาราง ยอดรวม ลายเซ็น และข้อความที่ค้นหา/คัดลอกได้
9. ตรวจจอเดสก์ท็อป/จอแคบให้ยังแก้เอกสารได้และ console ไม่มีข้อผิดพลาดจากการเปลี่ยนแปลง
10. repo เดิมและงานที่ยังไม่ commit ไม่ถูกเขียนทับ

## 9. โหมดเอกสาร — ผู้ใช้ยืนยัน 31 ตุลาคม 2026

หัวข้อนี้ใช้แทนรายละเอียดเดิมที่ขัดกัน ผู้ใช้ยืนยันให้พัฒนาตัว local Qut-Bill เท่านั้น

- Header ของทั้ง QUT และ BILL มี “อย่างง่าย / ข้อมูลเต็ม / กำหนดเอง” เริ่มแบบเต็ม รวมถึงร่างเก่าที่ไม่มีโหมด
- แบบง่าย QUT แสดงชื่อ “ใบเสนอราคาเบื้องต้น” ตารางรายการ และยอดคำนวณ โดยยังเลือกส่วนลด VAT ค่าใช้จ่ายเพิ่ม และใช้การคำนวณเดิมได้
- แบบง่าย BILL แสดงชื่อ “รายการชำระเงินเบื้องต้น” ตารางทุกงวด เปอร์เซ็นต์ จำนวนเงิน และยอดรวม
- แบบเต็มแสดงข้อมูลทุกส่วน กำหนดเองเปิด/ปิดเป็นส่วน: ผู้จัดทำ/ลูกค้า โครงการ เลขที่/วันที่/อ้างอิง เงื่อนไขชำระเงิน บัญชีธนาคาร หมายเหตุ และลายเซ็น; BILL เลือกวันครบกำหนดชำระแยกได้
- ตารางรายการและยอดรวมแสดงเสมอ การเลือกโหมดไม่เปลี่ยนสูตรหรือค่าคำนวณ การตั้งค่ายอดสรุป QUT ยังคงแยกจากการเปิด/ปิดส่วนข้อมูล
- ข้อมูลส่วนที่ปิดซ่อนทั้งหน้ากรอกและ PDF แต่ไม่ล้างค่า เปิดกลับมาแล้วข้อมูลเดิมยังอยู่
- จำโหมดและตัวเลือก custom แยก QUT/BILL ใน sessionStorage เหมือนอายุร่าง ไม่มีการจำข้ามครั้งเพิ่มเติม
- QUT เพิ่มช่องโครงการ เงื่อนไขชำระเงิน และวิธีชำระ/บัญชีธนาคารเพื่อรองรับส่วนข้อมูลที่ตกลง
- BILL เพิ่มที่อยู่/ข้อมูลติดต่อลูกค้าและวันครบกำหนดชำระ เก็บในร่างและแสดงใน PDF เมื่อเปิดส่วนนั้น
- BILL ยังแสดงทุกงวด ไม่เพิ่มการเลือกงวดเรียกเก็บ เปอร์เซ็นต์และเงินยังกรอกแยกกัน
- ปุ่มพิมพ์ BILL เตือนเมื่อส่วนที่เปิดขาดชื่อผู้วางบิล ชื่อลูกค้า เลขเอกสาร หรือรายการที่มีรายละเอียด/เปอร์เซ็นต์แต่ยังไม่มีจำนวนเงิน ให้เลือก “กลับไปแก้ / พิมพ์ต่อ” ไม่เตือนข้อมูลในส่วนที่ซ่อน
- จำนวนเงินที่รูปแบบผิดยังต้องแก้ก่อนพิมพ์ตามเดิม การยืนยันพิมพ์ต่อไม่ข้ามการตรวจนี้
- ไม่เปลี่ยน sibling Qut/Bill และไม่ commit/push/deploy

## 10. ปรับตารางและเมนู — ผู้ใช้สั่ง “ทำทั้งหมด” 31 ตุลาคม 2026

- BILL เหลือช่องจำนวนเงินเดียวต่อแถว ลบคอลัมน์ราคารวมที่ซ้ำกัน
- จำนวนเงินแสดง comma และทศนิยมสองตำแหน่งเมื่อไม่ได้แก้ไข คลิกเพื่อแก้ตัวเลขได้ รับการวางตัวเลขที่จัดกลุ่มหลักถูกต้อง และยังปฏิเสธรูปแบบผิด/ติดลบ/เกินขอบเขตเดิม
