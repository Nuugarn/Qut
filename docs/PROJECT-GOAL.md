# เป้าหมาย QUT / BILL: เลือกรูปแบบเอกสารจาก header

สถานะ: ส่งมอบและตรวจแล้ว — 31 ตุลาคม 2026
วันที่เริ่ม: 31 ตุลาคม 2026

## ความต้องการที่ผู้ใช้ระบุ
- ประเมินฟีเจอร์สำคัญที่ BILL ยังขาดสำหรับการใช้งานจริง
- มีตัวเลือกบน header สำหรับใบเสนอราคาอย่างง่าย (เบื้องต้น) หรือแบบข้อมูลเต็ม
- เลือกปรับเปิด/ปิดฟีเจอร์เอง (custom) ได้
- เก็บเป้าหมายไว้กับโปรเจกต์เพื่อให้ Codex ทำงานต่อจากบริบทเดียวกัน

## ขอบเขตที่ตกลงกับผู้ใช้ (รายละเอียดล่าสุดใน SPEC §9)
1. ยืนยันแล้ว: โหมดง่าย/เต็ม/custom ใช้ทั้ง QUT และ BILL
2. ยืนยันแล้ว: BILL แสดงทุกงวดตามเดิม ไม่เพิ่มการเลือกงวดเรียกเก็บ
3. ช่องข้อมูลและฟีเจอร์แต่ละโหมด รวมถึงผลต่อ PDF และสูตรคำนวณ
4. การสลับโหมดเมื่อกรอกข้อมูลแล้ว และอายุการจำการตั้งค่า
5. ฟีเจอร์ที่ควรเพิ่มก่อนใช้งานจริง และเกณฑ์ตรวจรับ

- Bill/index.html: ช่องผู้วางบิล เลขเอกสาร โครงการ และผู้ว่าจ้างไม่มี required; Bill/app.js printDocument ตรวจรูปแบบจำนวนเงินและ checkValidity แต่ไม่ได้ตรวจความครบถ้วนทางธุรกิจ ส่วน parseAmountCents ให้เงินว่างมีค่า 0
- Bill/app.js calcAll รวมทุกแถว ไม่มีสถานะเลือกงวดหรือยอดเรียกเก็บครั้งนี้
- มีเงื่อนไขชำระเป็นข้อความอิสระ แต่ไม่มีช่องวันครบกำหนดชำระโดยเฉพาะ

- ข้อเสนอให้พิจารณา: ตรวจความครบถ้วนก่อนพิมพ์ เลือกงวดเรียกเก็บ วันครบกำหนด และข้อมูลลูกค้าเพิ่มเติม ทั้งหมดนี้ยังไม่ใช่ฟีเจอร์ที่ได้รับการยืนยัน
- Q1 ผู้ใช้เลือก: ทั้งใบเสนอราคาและใบวางบิล
- Q2 ผู้ใช้เลือก: แสดงทุกงวดตามเดิม ข้อเสนอเลือกงวดเรียกเก็บจึงไม่อยู่ในขอบเขต
- ผู้ใช้ต้องการตอบคำถามด้วยตัวเลือกที่กดได้ ใช้ request_user_input_async สำหรับรอบถัดไป
- Q3 ผู้ใช้แก้ข้อเสนอ: โหมดอย่างง่ายมีเฉพาะรายการและการคำนวณเงิน พร้อมชื่อเอกสารประมาณ “ใบเสนอราคาเบื้องต้น”; ไม่ใช้ชุดข้อมูลชื่อผู้จัดทำ/ลูกค้า/ชื่องาน/เลขที่/วันที่ที่เคยเสนอสำหรับโหมดง่าย ต้องถามชื่อและขอบเขต BILL อย่างง่ายต่อ
- Q4 ผู้ใช้ตอบ “งง”: ยังไม่ยืนยันพฤติกรรมสลับโหมด/เก็บข้อมูล ต้องอธิบายด้วยตัวอย่างสั้นแล้วให้กดตอบใหม่
- Q4 ถามใหม่แล้วผู้ใช้ยืนยัน: ซ่อนข้อมูลเมื่อเปลี่ยนเป็นแบบง่าย และเปิดกลับเป็นแบบเต็มแล้วข้อมูลเดิมยังอยู่ ไม่ล้างค่าที่ซ่อน
- BILL อย่างง่าย ผู้ใช้ยืนยัน: ชื่อ “รายการชำระเงินเบื้องต้น” ตารางทุกงวด เปอร์เซ็นต์ จำนวนเงิน และยอดรวม
- ผู้ใช้ยืนยัน custom แบบเปิด/ปิดเป็นส่วน: ข้อมูลผู้จัดทำ/ลูกค้า ข้อมูลโครงการ เลขที่/วันที่ เงื่อนไขชำระเงิน บัญชีธนาคาร หมายเหตุ ลายเซ็น; ตารางรายการกับยอดรวมแสดงเสมอ
- ผู้ใช้ยืนยันแบบง่าย QUT ยังเลือกส่วนลด/VAT/ค่าใช้จ่ายเพิ่มได้ จึงไม่ตัดความสามารถคำนวณเหล่านี้ออกจากแบบง่ายตามข้อเสนอเดิม
- BILL แบบเต็ม: ผู้ใช้ยืนยันเพิ่มที่อยู่/ข้อมูลติดต่อลูกค้า และวันครบกำหนดชำระ; กำหนดเองเลือกซ่อนได้
- ก่อนพิมพ์ BILL: ผู้ใช้เลือกเตือนเมื่อข้อมูลผู้วางบิล/ลูกค้า/เลขเอกสารขาด หรือรายการยังไม่กรอกเงิน พร้อม “กลับไปแก้ / พิมพ์ต่อ”; ไม่เตือนช่องที่ซ่อนในแบบง่าย จำนวนเงินรูปแบบผิดยังใช้การตรวจเดิม
- โหมดเริ่มต้น: ผู้ใช้เลือกแบบเต็ม; จำโหมดแยก QUT/BILL ระหว่าง session และร่างเก่าเปิดเป็นแบบเต็มตามคำถามที่ผู้ใช้ตอบ
