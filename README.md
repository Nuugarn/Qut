# QUT / BILL

แอป static สำหรับใบเสนอราคาและแผนใบวางบิล แก้บนเอกสารโดยตรง
รวมอยู่ใน repo เดียว แต่แต่ละ section เก็บร่างและหน้าตาของตัวเอง

## เปิดใช้งาน

```sh
npm start
```

เปิด http://127.0.0.1:4173 แล้วกดชื่อเอกสารด้านซ้ายบน (▾) เพื่อเลือกใบเสนอราคา/ใบวางบิล
ไม่ต้อง npm install สำหรับการใช้งานหรือทดสอบสูตรเงิน
เปิด index.html โดยตรงได้ด้วย แต่ใช้ localhost เพื่อให้ session storage ทำงานสม่ำเสมอ
ถ้า browser ปิดกั้น storage จะมีข้อความเตือนว่าไม่สามารถจำร่างได้

## การกรอกและพิมพ์

- ตัวเลือก “รูปแบบ” บน header ใช้เลือกอย่างง่าย / ข้อมูลเต็ม / กำหนดเอง เริ่มแบบเต็ม
- โหมดและการเปิด/ปิดข้อมูลอยู่ภายในเมนู “รูปแบบเอกสาร” เดียว เลือกกำหนดเองแล้วจึงแสดงส่วนข้อมูลให้เลือก
- BILL กรอกจำนวนเงินช่องเดียว แสดงหลักพันและทศนิยมสองตำแหน่งเมื่อออกจากช่อง จำนวนเงินตัวอักษรใต้ยอดรวมเลือกเปิด/ปิดได้ในเมนูรูปแบบเอกสาร
- แบบง่ายเหลือชื่อเอกสารเบื้องต้น ตาราง และยอดรวม QUT ยังคงตั้งค่าส่วนลด/VAT/ค่าใช้จ่ายเพิ่มได้จาก “ยอดสรุป”
- ในเมนูรูปแบบเอกสาร เลือก “กำหนดเอง” เพื่อเปิด/ปิดส่วนข้อมูล ส่วนที่ปิดไม่แสดงใน PDF แต่ข้อมูลยังอยู่เมื่อเปิดกลับมา
- BILL แบบเต็มมีข้อมูลติดต่อลูกค้าและวันครบกำหนดชำระ ปุ่มพิมพ์จะแจ้งข้อมูลที่ยังไม่ครบและเลือกกลับไปแก้หรือพิมพ์ต่อได้
- โหมด/ตัวเลือกและร่างจำแยก QUT/BILL ในแท็บระหว่างใช้งาน เป้าหมายและข้อตกลงอยู่ใน docs/PROJECT-GOAL.md และ docs/SPEC.md

- QUT: จำนวน × ราคาต่อหน่วย งานเหมาใช้ 1 งาน × ราคา
- “ยอดสรุป” เปิดส่วนลดท้ายใบและเลือก VAT ไม่คิด/บวกเพิ่ม/รวมในราคา
- ส่วนลดหักจากสินค้า/บริการก่อนบวกค่าใช้จ่ายเพิ่มเติมและคิด VAT
- หากปิดส่วนลดหรือค่าใช้จ่ายเพิ่มเติม ค่านั้นจะไม่กระทบยอดรวม
- ประมาณการหัก ณ ที่จ่ายใช้ยอดสินค้า/บริการหลังส่วนลด ไม่รวมค่าใช้จ่ายเพิ่มเติมและ VAT เช่นแนวทางเดิม
- BILL: ใช้วิธีกรอกต้นฉบับก่อนรวม repo กรอกเปอร์เซ็นต์กับจำนวนเงินแยกกัน
- Header ทั้งสอง section ใช้รูปแบบเดียวกัน QUT สีน้ำเงิน/BILL สีเขียว; BILL เริ่มที่เอกสารเลย ไม่มีส่วนหัวหรือการ์ดสรุปซ้ำด้านบน
- เปอร์เซ็นต์ใช้เป็นข้อมูลอ้างอิง ยอดรวมคำนวณจากจำนวนเงินที่กรอก ไม่มีช่องยอดงานหรือโหมดคำนวณงวด
- ข้อมูลบริษัทใน BILL กดเลือกจากปุ่มข้อมูลตามเดิม ไม่เติมให้อัตโนมัติเมื่อเริ่มใบใหม่
- กด “พิมพ์ / บันทึก PDF” เพื่อเปิดหน้าต่างแบบ Ctrl+P แล้วเลือก Save as PDF หรือเครื่องพิมพ์
- แนะนำ A4, scale 100%, ปิด Headers and footers ของ browser; เอกสารหลายหน้าต่อให้อัตโนมัติ

## การจำข้อมูล

ร่างของแต่ละ section อยู่ใน sessionStorage ของแท็บเดียวกัน สลับ section และรีเฟรชได้
ไม่มีคลังเอกสาร cloud หรือไฟล์งาน PDF เป็นไฟล์ส่งออกอย่างเดียว
แท็บใหม่ที่ไม่ได้เปิดจากแท็บเดิมเริ่มร่างใหม่; browser อาจคืนร่างเมื่อใช้ Restore closed tab/session
ปุ่มล้างข้อมูลของ QUT ล้างเฉพาะร่าง QUT; BILL คงชุดปุ่มเดิมก่อนรวม

QUT ใช้ข้อมูลบริษัทตั้งต้นใน shared/workspace.js; BILL ใช้ปุ่มข้อมูลเดิม
แก้เฉพาะใบได้แต่ไม่เขียนกลับเป็น preset หรือนำไปเปลี่ยนเอกสารอีก section
เก็บ TH/EN เดิมไว้ การเปลี่ยนภาษาไม่แปลข้อมูลที่กรอกให้อัตโนมัติ

## โครงสร้าง

```text
index.html       ทางเข้า
Qut/             หน้าตาและ editor ใบเสนอราคา
Bill/            หน้าตาและ editor ใบวางบิล
shared/money.js  คำนวณเป็นสตางค์และปัดเศษอัตราส่วน
shared/workspace.js / .css  เมนูเลือกเอกสารที่ชื่อ, company preset, session, print mirrors
Bill/session.js  เพิ่มการจำร่างให้ BILL ต้นฉบับ รวมถึงอ่านร่างจากรุ่นรวมก่อนหน้า
tests/           ทดสอบสูตรเงินและ browser
docs/SPEC.md     สเปกที่ผู้ใช้ยืนยัน
```

เส้นทางภายในเป็น relative รองรับการวางใต้ subpath ไม่มี build step และไม่มีการเชื่อม QUT → BILL
Google Fonts เป็น resource ภายนอกเดิม; ถ้า offline จะใช้ font fallback ของเครื่อง

## ตรวจสอบ

```sh
npm test
```

การทดสอบ browser ใช้ Playwright ที่ติดตั้งไว้อยู่แล้ว กำหนด PLAYWRIGHT_MODULE
เป็นชื่อหรือพาธโมดูล และ BROWSER_EXECUTABLE เป็นพาธ Chrome/Chromium (ถ้าไม่มี bundled browser)
จากนั้นรัน `npm run test:browser` ผลลัพธ์และ PDF ทดสอบอยู่ใน artifacts/ ซึ่งไม่เข้า Git
ดู TESTING.md สำหรับผลที่ทดสอบจริง

Repo นี้สร้างใหม่จาก working copies ของ Qut/Bill ไม่ได้แก้หรือย้าย repo เดิม
ไม่มี Git remote, commit หรือ deployment รายละเอียดที่มาดู docs/PROVENANCE.md
